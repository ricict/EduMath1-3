# M6 — Visual Mathematics & Pedagogy

Status: **IN PROGRESS**

Started: **2026-10-06**

## 1. Purpose

M6 answers:

**How should EduMath turn semantic mathematical questions into developmentally appropriate child-facing visual representations while preserving the deterministic mathematics, localization separation, session semantics, and adaptive contracts already locked through M5?**

M6 consumes the semantic `Question` union produced by M3. It does not regenerate mathematics in React.

## 2. First vertical slice

The first M6 slice is deliberately limited to the two visual-semantic skills already required by the real Grade 1 adaptive entry path:

- `number_recognition_10`;
- `addition_concept`.

Current semantic inputs are:

```text
number-recognition
  target

addition-combine
  a
  b
```

No visual renderer may change those values or derive replacement mathematics.

## 3. Smallest rendering contract

M6 does not introduce a generalized graphics engine or visual-renderer registry yet.

The current boundary is:

```text
M3 semantic Question
        ↓
buildVisualQuestionModel(...)
        ↓
typed M6 visual model
        ↓
VisualQuestion
        ↓
React Native primitives
```

The pure visual-model function supports only the operations implemented in this slice.

Unsupported symbolic questions and later visual families return no M6 visual model. They are not silently treated as supported.

## 4. Number recognition

`number_recognition_10` renders its semantic `target` as a large numeral card.

This preserves the meaning of number recognition rather than converting the task into counting a generated collection of objects.

The renderer performs no randomization and does not inspect `expectedAnswer` to create the display.

## 5. Addition concept

`addition_concept` renders two separate counter groups.

The group counts are copied directly from:

```text
question.data.a
question.data.b
```

The visual model intentionally contains the two groups but not a computed total. The React component therefore has no reason to reproduce `a + b`.

This keeps mathematical generation and answer authority in M3/M4.

## 6. Localization and accessibility

Visible question wording remains owned by `src/localization/index.ts`.

M6 adds localized accessibility labels for:

- the shown numeral;
- the first object group;
- the second object group.

The visual component supplies only semantic interpolation values such as `target` and `count`.

Counter dots are visual children of an accessible group container, so assistive technology receives the equivalent group quantity rather than a sequence of unlabeled decorative elements.

## 7. Responsive layout

The first slice uses React Native flex and wrapping primitives.

Addition groups can wrap when horizontal space is narrow and can sit side-by-side when space permits. No fixed phone/tablet breakpoint or canvas engine is introduced because the current requirement does not justify one.

## 8. Determinism

M6 visual rendering introduces no new PRNG and no visual randomness.

The visual model retains the deterministic question ID and consumes the exact semantic quantities already generated by M3.

Rendering the same semantic question therefore yields the same mathematical visual content.

## 9. Answer interaction

The first child-facing M6 integration supports `numeric-choice` questions.

This includes the new visual number-recognition and addition-combine questions as well as compatible symbolic numeric questions.

The practice controller now rejects a newly recommended non-numeric question type before persisting that new session and exposes an explicit unsupported-practice state instead of submitting incompatible numeric answers.

M6 still does not manufacture distractors or answer-option mathematics in the visual component. A future change to answer-option semantics should be represented explicitly in the question contract rather than hidden in React.

## 10. Concrete → visual → abstract

M2 representation metadata remains the authority for which representation categories are valid.

Concrete → visual → abstract progression is a pedagogy-policy concern that may select among valid representations later. It is not encoded as a renderer-side progression rule in this first slice.

The current two generators explicitly request `visual`, so M6 renders that representation only.

## 11. Testing strategy

The visual-model boundary is pure TypeScript and is tested without screenshots.

Tests verify:

- exact consumption of the number-recognition target;
- exact preservation of addition group counts;
- absence of renderer-side answer calculation;
- explicit non-support for symbolic questions;
- explicit non-support for later visual families;
- localized accessibility interpolation.

The React component remains thin over the tested visual model.

## 12. Adaptive/session integration

After the first visual slice passed CI, the child-facing practice controller was connected to the existing M5 `startRecommendedPractice(...)` bridge.

The integration rules are:

- an existing resumable M4 session is still resumed first;
- when a fresh session is needed, M5 selects the Grade 1 skill and difficulty;
- zero-history Grade 1 therefore starts at `number_recognition_10`, difficulty 1;
- the returned M4 session and first M3 question are persisted only when the current practice screen supports their question type;
- unsupported M5/M3 states remain explicit and never trigger an unrelated fallback;
- completing a session preserves M4 history so the next fresh session can recompute M5 mastery and recommendation.

The screen no longer claims that every session is `addition_within_10`; it displays the active grade and difficulty generically.

## 13. Current boundary

The first M6 vertical slice now reaches the real adaptive Grade 1 entry path for supported numeric-choice practice.

The current child-facing answer interaction does not yet support `relation-choice`, `fraction-choice`, or `time-choice`.

Fractions, clocks, number lines, shapes, pictograms, tables, and charts remain future M6 work and must extend the contract only when their concrete requirements are implemented.
